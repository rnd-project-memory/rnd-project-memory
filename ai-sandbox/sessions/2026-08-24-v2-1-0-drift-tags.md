## Objective

Act on three follow-ups the user raised after reviewing yesterday's `v2.0.0` work: why the three
stray `CHECKPOINT-<owner>.md` references survived the migration's own verification, a mechanical
check for that class of miss going forward, and a mechanical check for `.template-version` naming
a `skeleton/` state it no longer has — then cut and tag `v2.1.0`.

## Reasoning

The stray references got past `MIGRATIONS.md`'s v2.0.0 Verification because that section checks
filenames ("no file named `CHECKPOINT-<old-owner>.md` remains"), and the misses were in prose. The
user's fix — a `check.sh` "Retired vocabulary" check, scoped to exactly the four paths
`MIGRATIONS.md`'s own Exceptions already name — is cheap and needs no separate exclusion decision.
Implemented directly (`0dfded5`), plus a step in `MIGRATIONS.md`'s "Cutting a release" procedure
so the next MAJOR's retired terms feed the same array without rediscovering the pattern.

Two illustrative uses of the retired string in `RND_PROJECT_MEMORY.md` (an explanatory sentence
and a worked example) had to be reworded rather than exempted — adding the handbook as a fifth
exclusion path would have broken the "the list is already `MIGRATIONS.md`'s Exceptions, no
separate decision" property the check was designed around.

The third fix (`3e49d7b`) is the same class of problem one level up: `.template-version` had kept
claiming `skeleton @ f1a6d6f` through two follow-up commits that changed `skeleton/`. Fixed with a
mechanical check, gated on a local `skeleton/` directory existing at all — true only for this
repository's self-hosting setup (ADR-006), a silent no-op for every ordinary consumer.

**Tagging.** Discovered while addressing point 2 that `v1.0.0`/`v1.1.0`/`v1.2.0` already exist as
annotated tags, correctly placed on the artefact/release commit (matching `.template-version`'s
`skeleton @ <sha>` — e.g. `v1.2.0` → `b00b3b8`), not on the "chore: upgrade the root memory"
commits the user's `3bab1de`/`8ea40f5` pointed at. Asked which convention to extend; kept the
existing one. `v2.0.0` retroactively tagged at `f1a6d6f` (the settled skeleton state at release),
`v2.1.0` tagged at `3e49d7b` (`skeleton/`'s last commit for this batch of fixes).

## Decisions

- `check.sh` gains two new advisory blocks: "Retired vocabulary" and "skeleton/ vs
  `.template-version`". Neither blocks a commit; both are always-0 like every other `check.sh`
  block.
- `MIGRATIONS.md`'s "Cutting a release" procedure gains a step tying a MAJOR's retired
  terminology (already named in that section's Reason) into `check.sh`'s `RETIRED` array.
- Tags follow the existing artefact-commit convention, not a new one. `v2.0.0` and `v2.1.0`
  created; `v1.0.0`–`v1.2.0` untouched.
- `.template-version` bumped to `v2.1.0  skeleton @ 3e49d7b`, last, after everything else settled.
